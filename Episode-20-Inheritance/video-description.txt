A developer and a manager have different jobs, but both have a name and an employee ID. Copying the same code into every class makes it hard to maintain. In this lesson, you learn C# inheritance: put the shared code in one base class, and let derived classes reuse it. We build a real Employee, Developer, and Manager app in VS Code, step by step.

This is episode 20 of the Complete C# Course for Beginners on ITHubCoding. It continues from the episodes on classes, constructors, and encapsulation. Earlier episodes are in the course playlist.

WHAT YOU WILL LEARN
• Why duplicated code is hard to maintain
• Base classes and derived classes (parent and child classes)
• The colon: public class Developer : Employee
• Using inherited members: Name, EmployeeId, and ShowDetails() on a Developer object
• Why private members stay private, even in a derived class (error CS0122)
• Adding specialized members: ProgrammingLanguage for developers, TeamSize for managers
• Constructors and base(...): why the build fails with CS7036, and how base passes values to the base constructor
• Constructor order: the base class constructor runs first
• When to inherit: the "is a" test, "has a" relationships, and only one direct base class (error CS1721)
• Common mistakes: forgetting the colon, and repeating an inherited member (warning CS0108)
