Then we refactor the real Number Guessing Game from episode 12 into five small methods, and prove it still works. WHAT YOU WILL LEARN
• What a method is: a named block of code that does one job
• Declaring a method vs calling it (a method that is never called never runs)
• The parts of a declaration: static, void, the name, the parameter list, and the body
• Parameters vs arguments: the variable in the declaration vs the value in the call
• Return values: the return type, the return statement, and storing the result
• void vs int vs bool
• Refactoring: improving the structure of code without changing what it does
• Common mistakes: never calling a method, the wrong argument type (CS1503), a missing return (CS0161), and a mismatched return type (CS0029)

THE PROJECT
NumberGuessingMethods is episode 12's game, copied into a new project and split into methods:
• static void ShowWelcome() prints the title and the instructions
• static int GenerateSecretNumber() returns random.Next(1, 101), a number from 1 to 100
• static int GetValidGuess() asks until the guess is a whole number from 1 to 100, then returns it
• static bool CompareGuess(int guess, int secretNumber) prints the hint and returns true only for a correct guess
• static int PlayGame(int secretNumber) runs the loop and returns the number of attempts
The top-level code now reads like a story: ShowWelcome, GenerateSecretNumber, PlayGame, then the result. Text, 0, -5 and 101 are rejected, and invalid entries never count as attempts.

TESTED
Every version was built and played automatically (72 real games), and the methods were tested with known values: CompareGuess(50, 50) is the only call that returns true, GenerateSecretNumber returned only 1 to 100 in 200,000 calls (100 included), and PlayGame counted only valid guesses.
