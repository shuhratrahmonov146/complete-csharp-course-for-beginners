Abstract class or interface? Both describe what other classes must do, so beginners often ask: what is the actual difference, and when should I use each one? In this lesson, we answer that question by building a real e-commerce payment system in VS Code: an abstract PaymentMethod base class for what every payment IS, and two interfaces, IRefundable and IReceiptSender, for what a payment CAN DO.

This is episode 25 of the Complete C# Course for Beginners on ITHubCoding. It continues from episode 23 (abstract classes) and episode 24 (interfaces). The full course is in the playlist.

WHAT YOU WILL LEARN
• What abstract classes and interfaces have in common
• Abstract class: shared data, a constructor, implemented and abstract methods
• Interface: a contract, or a capability (and why default interface methods are an advanced extra)
• The key difference: shared state versus capability ("is a" versus "can do")
• One base class, many interfaces: CreditCardPayment : PaymentMethod, IRefundable, IReceiptSender (and why two base classes give CS1721)
• Implementing interface members (CS0535 when one is missing)
• Using a capability safely with the is keyword (CS1061 without it)
• A side-by-side comparison and a simple decision guide
• Common mistakes: CS0144, CS1722, CS0534

THE PROGRAM
EcommercePaymentSystem (a local simulation: no real payments, no card data): an abstract PaymentMethod (PaymentId, Amount, a protected constructor that rejects amounts of zero or less, DisplayPaymentInformation, abstract ProcessPayment) and two interfaces, IRefundable and IReceiptSender. CreditCardPayment implements both; in our example store, PayPalPayment only sends receipts. Real output:
Payment ID: P-1001
Amount: 120.50 USD
Charging card ending in 4242.
Receipt emailed for P-1001.
Refunded 20.00 USD to the card.

Payment ID: P-1002
Amount: 45.99 USD
Paying via PayPal: ali@example.com
Receipt sent to ali@example.com.
Refunds are not supported.

YOUR CHALLENGE
Build a simple document management system.
Create an abstract class called Document with a Title property and an abstract method called Open().
Then create two interfaces:
- IPrintable with a Print() method.
- IShareable with a Share() method.
Create a PDFDocument class that inherits from Document and implements both interfaces.
Create another document type that supports printing but does not support sharing.
Explain why the abstract class and interfaces are useful for this design.
Try to solve it on your own first!
